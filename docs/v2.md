# Model Economist 2.0

The ranking unit remains `(model, effort)`. A Context Planner chooses a bounded context envelope and an execution topology before the existing assessment and economic ranking. An Economics Observer records usage, cache and verified outcomes after execution. Floors, retries, role preferences and scoped-model constraints remain in the original decision pipeline.

## Start with a preset

`/economist` opens the settings panel (a Pi overlay drawn with the host theme). Choose Economy, Balanced, Quality, Adaptive or Custom under Priority, then a Control level; the preset's consequences appear in the draft before saving. Ctrl+S commits the draft and keeps the panel open. Esc leaves a choice list without applying it; on a draft, the first Esc warns and the second discards. No navigation makes provider calls.

- **Economy**: cost policy, smaller retrieval envelope, earlier compaction pressure threshold.
- **Balanced**: cost/quality/latency policy, selective retrieval and moderate compaction threshold.
- **Quality**: higher floors (existing higher floors are preserved), larger retrieval envelope, later compaction; exploration off.
- **Adaptive**: fixed quality floors, expected-cost fallback and bandit shadow recommendations. Measured evidence gates activation.
- **Custom**: retain independent routing axes and expose the legacy controls.

Safety thresholds never change with presets. Control has three values: `automatic`, `ask` (confirm before replacing host compaction or executing a worker), and `advisory`. A legacy Economy/Balanced/Quality policy maps to that preset without reapplying defaults; Latency maps to Custom. Independent cadence, effort, model pool, budget, privacy and role preferences are retained. Loading never rewrites configuration or activates a new feature. New configuration starts at Balanced/advisory/observe. Explicit Automatic/Ask control authorizes the corresponding deterministic operations.

`/economist migrate --preview` shows a complete field diff without writing. `--write` explicitly saves it. The proposed `version: 2`, `optimizer.context/cache/routing/delegation/learning`, `classifier.mode`, `roles`, `budget` and `privacy` vocabulary is supported alongside legacy aliases. Human edits keep aliases synchronized; project/global precedence and locks apply equally to either spelling. Global migration reads the global section and never copies project configuration or locale into it. Task, session and project budgets persist and cover classifier, executor, worker and compaction charges; unknown prior spend fails closed under a finite budget.

For deterministic context optimization, choose a preset and Automatic/Ask, then Ctrl+S. That explicit first-use control choice enables deterministic optimization; no knowledge of rollout settings is required. Advanced still exposes Observe, Shadow and canaries for controlled measurement. Selecting Adaptive starts in Shadow and requires evaluation evidence before activation. Later sessions keep the saved selection.

```yaml
modelEconomist:
  configVersion: 2
  preset: balanced
  control: automatic
  rollout:
    stage: active
```

Candidate setup remains Pi's scoped/authenticated model metadata workflow. Config writes touch only `modelEconomist`; nested global locks also constrain presets and dashboard writes. Locale is project-local and defaults to English.

## Runtime and compatibility

Node >=22.19.0; supported peer range Pi 1.5.2–1.5.x. The real-loader and native TUI smoke targets installed Pi 1.5.2. No claim is made about untested providers or other Pi minors. The capability probe distinguishes available functions, unavailable adapters, hooks not yet seen (`unknown`), and hooks actually observed. Registration alone is not a capability test.

Primary API references: [Pi extension API](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/extensions.md), [Pi compaction API](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/compaction.md). The adapter follows the installed 1.5.2 type declarations, including `CompactionPreparation`, `CompactionResult`, context messages and provider payload replacement. No provider inference is used in local verification.

## Context discovery and retrieval

Large non-error, text-only tool results become bounded previews with `econ:<sha256>` handles in the outgoing context. The original transcript is not rewritten. Mixed image/tool content and errors are preserved. Externalization refuses oversized artifacts or full stores, retaining the original output. A handle is emitted only after its complete redacted content has been stored successfully.

Operational content lives under the project-scoped suite state directory:

```text
projects/<canonical-project-id>/.context/artifacts/
  <hash>.txt       # redacted recoverable evidence, not an audit log
  <hash>.json      # bounded symbol/reference metadata
```

The default limits are 2 MB per artifact, 32 MB total, 1,000 artifacts and seven days retention. Handles referenced by committed structured checkpoints are pinned against expiry; pinned evidence still counts toward capacity, and a full store falls back to retaining context. Files are private (0600 on supported platforms), directories 0700; Windows ACLs follow the user's profile. Content-addressed integrity is verified on reads. Handles cannot address arbitrary paths. Explicit file indexing rejects escapes, links, secret files and binaries; it does not scan the user's home or credentials. Indexing a known file is exposed through the local `ArtifactStore.indexFile()` integration API.

`economist_retrieve({handle, offset, budgetTokens})` recovers paginated evidence; `{path, budgetTokens}` indexes a permitted project file; `{query, budgetTokens}` searches lexical overlap, symbol definitions, symbol-reference proximity, recency and optional local vector features. Active read/edit/write observations update the index automatically. Terminal, MCP, tool, file, checkpoint and episode evidence retain their logical kinds. Token budgets are hard bounds. Irrelevant queries abstain. Retrieval text is labeled as evidence, never authorization, and is excluded from human checkpoint invariants.

Automatic retrieval has a built-in VOI model using the existing routing posterior, failure/recovery cost, candidate relevance and incremental token prices. Its forecasts are labeled estimated; paired verified feedback can replace the forecasted gain after 30 observations. Unknown economics abstain. An optional `contextVoi` adapter can refine this policy but is not required. Optional local hashed vector features require no model download, vector DB or remote embedder; they are not represented as neural semantic embeddings.

Verified integrators may emit `economist:context_feedback` with `source: test|gate|ci`, `verified: true`, `utilizedHandles` and `expectedHandles`. Only then can utilization and retrieval precision/recall be reported. Mixed-use token attribution stays unknown when no per-artifact measurement exists.

## Structured and adaptive compaction

`session_before_compact` preserves the host's `firstKeptEntryId`. Human messages and custom constraints are retained as invariants. Decisions/rationale, artifacts, file changes, verified test commands, open questions, risks, next actions and recovery handles live in a versioned structured checkpoint. Prior structured checkpoints are merged incrementally. Opaque non-user evidence is externalized as a recoverable episode before it can leave the window. A malformed previous summary is preserved as an invariant rather than silently dropped.

Compaction falls back to the host if evidence cannot be stored, invariant size exceeds the checkpoint budget, the summary does not reduce size, or fidelity is insufficient. A roundtrip validation does not establish semantic correctness; retention tests separately probe human constraints, rationale, files, tests and handles across three successive compactions. Fidelity uses the specification's assumed weights (0.35 constraints, 0.25 decisions, 0.20 artifacts, 0.20 tests).

Adaptive timing combines occupancy, unused-content evidence where available, next-step overflow risk and degradation evidence. Available pressure weights are normalized; unavailable measurements are not represented as observed zeros. The built-in economic estimator supplies keep/compact/loss costs from prices, cache forecasts, recovery cost, checkpoint size/fidelity and the task horizon. Local deterministic extraction has zero inference API cost; its actual duration is tracked separately. Economic benefit can trigger compaction before overflow. Host lifecycle boundaries persist incremental checkpoint/episode candidates before a critical threshold; no hidden background inference or independent thread is started. Metrics commit only after the host confirms `session_compact`; native host compaction usage is also accounted. Late callbacks cannot change another session. The specification explicitly postpones learned compaction until sufficient data; this release's default timing policy remains deterministic and calibratable.

## Cache and cost accounting

Every reported quantity distinguishes `observed`, `derived`, `estimated` and `unknown`. Pi's `usage.cost.total` is a metadata-derived cost, including a valid zero; it is not an invoice. Explicit `billedCostUsd` can supply an observed provider charge. Costs and cache observations are collected even when a separate cost-profiler extension owns the shared budget journal.

Dashboard `cacheHitRate` is the fraction of calls with observed cache reads that read at least one cached token. `cachedTokenFraction` is the separate token-weighted ratio. Observed and unknown call counts expose coverage; unknown calls are excluded from hit frequency and prevent a complete token ratio. Tool-output retention/externalization accounting identifies each result by call, timestamp and content hash, so replaying a transcript updates the observation instead of counting it again. Small retained text results are included.

Pi input tokens exclude cache reads/writes; OpenAI-compatible input totals include cache reads; Anthropic-style observations provide separate components. Normalizers preserve missing counts; provider usage takes precedence over host default counts. `economics/providers.mjs` contains versioned contracts with primary-source links: OpenAI in-memory/extended retention is an explicitly uncertain documented estimate; Anthropic ephemeral retention follows the request's cache controls. Explicit host metadata overrides documented defaults, and unknown provider/proxy retention remains unknown. Prices always come from host metadata. There is no universal TTL or arbitrary 0.5 hit probability. Forecasts expose prefix, TTL and provider-affinity terms with provenance and uncertainty; a cache-hit event is distinct from the fraction of cached tokens.

Prefix keys hash provider/model, the effective system prefix, deterministic full tool schemas, project policy and context generation. Raw prompts are never cache keys in the journal. Tool ordering changes alone do not invalidate the key; schema/system/policy changes and compaction do. Full tool definitions and system message ordering are preserved. Unknown retention yields a labeled cold-cost forecast, not an invented hit probability.

`effectiveInputCost` decomposes uncached input, cache reads and cache writes once. The operation ledger accounts for retrieval, refetch, compaction, cache rewarming, handoff and rework, distinguishing direct API charges from token costs already included in the provider request. The ranker combines these with classifier and verifier-driven recovery costs, including another eligible retry and refetch after compaction. It does not subtract cache savings or add input attribution twice. Worker costs contribute to CPVS and all applicable budgets. Native compaction is counted whether or not the shared cost profiler captured it. Failed delegations with unknown spend remain unknown and cannot bypass a finite budget. Cost error is mean absolute per-call error, so under/overestimates cannot cancel. Money remains separate from measured local latency and policy latency utility. Legacy advisory/observe keeps the original ranking as the comparison baseline.

Switch hysteresis considers incremental request/retry/cache costs, premiums and cooldown. It applies only inside the already feasible quality/safety set. Infeasible current actions, hard-risk checkpoints, retries and explicit role preferences bypass retention. Unknown switching costs retain a feasible current action. No cross-model KV reuse is claimed.

## Adaptive routing and evaluation

Advanced algorithms: `expected-cost`, `cascade`, `bandit`. Cascades choose the cheapest already feasible action and rely on the existing verifier-driven escalation ladder. Family-conditioned UCB bandit proposals use verified outcomes, bounded exploration premium and no exploration under hard risk. Shadow is the default. Active selection additionally needs sufficient family samples and approved paired evidence; deterministic fallback remains available. The logged propensity is 1 for these deterministic choices. No randomized exploration probabilities are fabricated. Economic actions expose success, cost and latency distributions with assumptions/provenance; the causal explanation shows floors, cache confidence, stay/switch request/recovery differences and net gain. The dashboard prioritizes CPVS, session cost, context/cache and compaction fidelity, with privacy and advanced controls behind submenus.

`/economist evaluate FILE.jsonl` performs offline six-arm paired replay: `v0.4`, `context`, `cache`, `routing`, `context+cache`, `full-adaptive`. No model is called. Each row requires:

```json
{"taskId":"synthetic-example","seed":1,"arm":"context","model":"same-model","version":"same-version","provider":"same-provider","commit":"same-commit","toolsHash":"same-tools","timeoutMs":10000,"verifier":"same-verifier","verified":true,"success":true,"costUsd":0.1,"prediction":0.98,"latencyMs":100,"qualityFloorSatisfied":true,"safetyFloorSatisfied":true,"strata":{"task":"read","cache":"warm"}}
```

Pairs must match task, seed and all experimental controls. Duplicate arms fail validation. Missing costs/outcomes are excluded, never imputed. Bootstrap resamples independent tasks with all their seeds together. The report includes CPVS (failed attempts remain in the numerator), input/cache tokens, retrieval precision/recall, compaction fidelity, post-compaction success, rework, switches, Brier/ECE, latency/TTFT, strata, paired intervals and improvement probability. Data marked synthetic cannot activate learning. Dataset provenance and verifier independence remain the operator's responsibility; a `measured` field is not cryptographic evidence.

Acceptance gate version 3 additionally requires complete paired coverage: excluded outcomes/costs and unmatched experimental controls are counted in `excludedPairs`, `unmatchedBaseline` and `unmatchedTreatment` and block activation. Full Adaptive requires all six measured arms. Missing latency or prediction in any evaluated pair makes its corresponding metric unknown, rather than silently improving a percentile or calibration score by dropping that observation. Invalid numeric domains, probabilities, retrieval counts and control types are rejected. Configuration can raise the independent-task minimum but cannot lower it below 30. Reports from older gate versions require reevaluation before activation or rollback clearance.

Adaptive activation checks every applicable MVP/Beta/GA gate: at least 30 independent measured tasks and 30 pairs; cost-error mean <10%; constraint recall and compaction fidelity >=95%; uncached-input reduction >=20% on bulky outputs; upper 95% quality-regression interval <=1 percentage point; CPVS improvement >=15%; p95 within +15%; ECE <=0.08 and Brier within +0.01; switch-induced cache-miss reduction >=30%; retrieval precision >=0.70; post-compaction success regression <=2 percentage points; improvement probability >0.95; explicit floor evidence and zero violations. Missing measurements fail the gate and are named in `missingOrFailed`. The evidence is bound to the project's candidate pool, floors, thinking, privacy and context/cache policy; changing them invalidates activation evidence. These are assumed product acceptance criteria, not empirical results claimed by this implementation.

Additional measured-row fields are `provenance: measured`, `actualCostUsd`, `estimatedCostUsd`, `inputTokens`, `uncachedInputTokens`, `cacheReadTokens`, `cacheWriteTokens`, `bulkOutput`, `constraintRecall`, `compactionFidelity`, `postCompaction`, `retrievedCount`, `relevantRetrievedCount`, `requiredRelevantCount`, `switchCacheMisses`, `modelSwitches`, `reworkTurns` and `ttftMs`. `/economist off-policy FILE.jsonl` runs IPS/SNIPS from logged `propensity` and `targetProbability`, reporting effective sample size and overlap limits. Deterministic logs cannot identify unchosen actions. Both commands run in an owned worker thread with memory, matrix-size and time limits; Esc cancels in the native UI, and shutdown awaits termination. Malformed JSON reports only the line number, keeping matrix content out of errors.

Rollout stages: Observe → Shadow → Canary 5% → Canary 25% → Active. Stage selection is explicit; stable hashed session/turn keys choose canary exposure. Quality, cost, ECE, safety and compaction-fidelity regressions stop optimization and persist a project-scoped rollback event. Reconfiguration and session restarts never silently clear rollback. A new explicit evaluation with eligible paired evidence clears it. Comparisons require enough current observations; absence of data is not evidence of improvement.

## Delegation

`economist_subagent_model` remains advice-only. `economist_delegate` executes a bounded contract only when saved control/topology permits it, the rollout allows it and no hard risk is present. The shipped `PiWorker` uses the host's real `@earendil-works/pi-agent-core` Agent. It has an independent transcript, tool set, persistent cache/session identity, cost/token/turn accounting and cancellation. It calls only the chosen approved physical model through the host registry; no credential is read by this extension and no parent transcript is copied. Model and thinking are chosen through the same scoped router/floors as the lead.

Native worker tools enforce the relative file allowlist, protected-path rules and read/write/test permissions. Writes target existing files only and verify the opened file identity. Built-in tests are JSON, literal-content and JavaScript syntax verifiers; they do not grant arbitrary shell execution or run repository scripts. Syntax verification gets a minimal environment without preload hooks or credentials. Request preflight reserves a conservative UTF-8/BPE text-input bound and capped output against remaining tokens and USD; usage is checked after each response, with retries disabled. An unknown price/usage cannot establish a bounded successful handoff. A stopped job reports partial changes for lead review. Context isolation and these tool capabilities are not advertised as an OS sandbox.

An optional `worker` adapter can replace the native implementation. It must declare and enforce `isolatedContext`, `enforcesBudgets` and `enforcesPermissions`, implement `execute(contract, {signal, model, thinkingLevel})`, and optionally `dispose()`. Ask control offers Allow once, Always for this trusted project and Cancel, with the selected model/provider, expected cost/latency, file permissions and hard budget shown before dispatch.

Topology selection uses mechanicality × separability × verifiability − ambiguity − context coupling. Unknown topology features retain single-agent execution. A worker result is `done`, `blocked` or `needs-review` with summary, files, tests, artifacts, unresolved items and usage provenance. Missing checks or truncated output require review. Worker success is counted only after a verifier outcome for the lead's route; rework cost is attributed separately. Cancellation, timeout and shutdown abort the worker and await idle/cleanup. The default integration creates no clone/worktree, persisted Pi settings/session, new provider or cloud service. It may launch Node in parse-only `--check` mode for an explicitly requested syntax verifier.

## Verification and boundaries

`npm test` runs synthetic offline unit/integration tests. `npm run test:host` uses the installed Pi loader, theme and keybindings with synthetic registry metadata: ↓/Enter/Ctrl+S/Esc on the panel, the pool and simulation screens, an isolated copy without `node_modules/pi-tui`, 40/80/120 column rendering and the real loader's offline evaluation thread. Its native Agent smoke also checks allowlisted writes, independent worker identities, verification and cancellation/idle cleanup through a synthetic stream. `npm pack --dry-run` checks module inclusion without publishing. The package is private.

These checks establish implementation behavior, including recoverability, preserved constraints, >20% synthetic outgoing-context reduction, native worker execution against a controlled stream, and fail-closed acceptance gates. They do not establish real provider cache hit rate, <10% billing error, >=15% CPVS improvement or real-workload latency/quality non-regression. Those require the comparable measured matrix specified above. Human Windows Terminal resizing and paid-provider validation are separate from the headless smoke. The specification's research references and postponed learned-compaction/parallel-routing ideas are not represented as trained production algorithms.
